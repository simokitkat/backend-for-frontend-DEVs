# Front End Department / Back End Course / Group A1

## What this course is about

The Back End training for Front End developers is meant to raise their skills against current market requirements and to build a T-shaped profile: a broad outlook with deep expertise in a core area.

> The assignment is the same for every participant, _**but any part of it can be adjusted for an individual participant in agreement with the mentor.**_

## Tools

Any tools are allowed, including artificial intelligence, at every stage of the work. The participant must still be ready to give a complete, reasoned justification for every technical decision at the interim reviews and at the final review with the mentor. If the tools differ from those recommended in the assignment, agree on them with the mentor.

## Mentors

Each participant is assigned a mentor according to their level of preparation and their location.
Every week the mentor collects the current status of the practical assignment.

> _**At any point in the training, participants can ask the mentor for theoretical and technical advice.**_ To arrange a meeting, contact the mentor and book a time in the calendar.
> A participant who shares an office with the mentor can also ask in person, without arranging it in advance.

### Final result

By the end of the course there is a backend service: a monolithic HTTP API with a relational database, access checks on operations, and background jobs. A separate frontend is not required. Every scenario is called from an HTTP client.

The service registers users and, when required, confirms email, signs them in with access and refresh cookies, manages roles and permissions, and authorizes protected operations. A user reads and updates their profile and deletes the account. An administrator maintains the user list, roles, and other people's profiles. The same service transforms text files and images, returns the history of operations, and, on request, saves the results to object storage.

#### Node.js

> A boilerplate for starting a new monolithic project on NestJS.
> It contains the base modules and connections.
> [https://github.com/pavel-skripko-innowise/nestjs-monolith-boilerplate](https://github.com/pavel-skripko-innowise/nestjs-monolith-boilerplate)

#### .NET

> A project template for starting a monolithic Web API on .NET Core.
> It contains a basic API endpoint, `/health`, which confirms that the service is running.
> OpenAPI is enabled in the Development environment.
> The template currently provides only the OpenAPI document. A Swagger UI is not included.
> The test project uses xUnit and checks that a GET request to `/health` returns 200 OK.
> [https://github.com/pavel-skripko-innowise/dotnet-minimal-webapi-boilerplate/](https://github.com/pavel-skripko-innowise/dotnet-minimal-webapi-boilerplate/)
